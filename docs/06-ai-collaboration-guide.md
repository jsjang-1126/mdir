# AI 협업 가이드 — 비슷한 프로그램을 의뢰하는 방법

이 문서는 **mdir 개발에서 효과적이었던 요구 방식**을 정리합니다.  
앞으로 TUI·CLI·서버 도구를 AI에게 맡길 때 참고하세요.

---

## 1. 좋은 첫 요구 예시 (mdir 실제)

### ✅ 효과적이었던 요구
> Ubuntu에서 윈도우 탐색기 같은 걸 **텍스트 화면**으로 만들 수 있을까?  
> Python + Textual로 `mdir` 폴더에 만들어 줘.  
> 2패널, 미리보기, 북마크, 터미널 크기에 맞는 전체 화면까지.

**왜 좋은가:**
- **플랫폼** (Ubuntu/Linux)
- **UI 형태** (TUI, 텍스트)
- **참고 모델** (윈도우 탐색기 / MC 스타일)
- **기술 스택** (Python + Textual)
- **출력 위치** (`mdir` 폴더)
- **범위** (핵심 기능 나열)

### 이후 추가 요구도 구체적이었음
> `v`는 vim, `n`은 nano  
> 하단 상태바에 수정일시  
> 셸 어디서든 `mdir` 실행  
> iwin 서버에 배포

→ **한 번에 하나의 명확한 기능** + **키/동작 지정**

## 2. 요구 템플릿 (복사해서 사용)

```
[프로그램명] 을(를) 만들어 줘.

환경: Ubuntu 서버 / SSH 터미널
형태: TUI (Textual) / CLI / 데몬 중 택1
참고: (예: Midnight Commander, lazygit, btop)
폴더: ~/apps/프로젝트명

필수 기능:
- ...
- ...

단축키 (있으면):
- F5: ...
- q: 종료

제외:
- GUI는 필요 없음
- ...

배포: 로컬 PATH + (선택) 원격 서버 SSH Host 이름
```

## 3. mdir에서 AI가 잘 해낸 패턴

| 패턴 | 설명 |
|------|------|
| **점진적 구현** | 뼈대 → 실행 확인 → 버그 수정 → 기능 추가 |
| **직접 실행 검증** | `python -m mdir`, Textual `run_test`, SSH 배포까지 AI가 실행 |
| **버그 리포트에 증상 포함** | 스크린샷, 에러 traceback, "연두 테두리는 패널1인데 키는 패널2" |
| **환경 정보** | venv 오류, Windows SSH config 내용, 서버 Host 이름 |
| **명시적 우선순위** | "터미널 리사이즈는 전체 화면만 되면 됨" → 과도한 구현 방지 |

## 4. 버그/수정 요청 시 좋은 형식

### ✅ 좋은 예
> 북마크 창 닫으면 패널1 테두리인데 키는 패널2에서 먹혀.  
> `c`, `Esc`는 되는데 `Enter`는 안 돼.

→ **기대 동작** vs **실제 동작** + **재현 키**

### ✅ 더 좋은 예
> traceback 붙여넣기 + 스크린샷

### ⚠️ 아쉬운 예
> 안 돼. 고쳐 줘.

## 5. 기술 스택 선택 가이드

| 목적 | 추천 | mdir |
|------|------|------|
| 빠른 TUI 프로토타입 | Python + Textual | ✅ 사용 |
| 단일 바이너리, 고성능 | Rust + ratatui | — |
| 서버 배포 간단 | Go + bubbletea | — |
| 학습/레거시 | C + ncurses | — |

**mdir처럼 SSH 서버 도구** → Python + Textual이 설치·수정·배포 모두 쉬움.

---

## 6. 배포 요청 시 제공할 정보

AI가 원격 배포까지 하려면:

1. SSH `Host` 별칭 (예: `iwin`)
2. `HostName`, `User`, `IdentityFile` 경로
3. **키 파일을 어디에 둘 수 있는지** (Windows만 있으면 lg-note로 scp 필요)
4. 원격 설치 경로 (기본 `~/apps/프로젝트명`)

mdir 사례:
- Windows config는 AI가 직접 못 읽음 → 사용자가 Host 블록 **붙여넣기**
- `scp iwin_key lg-note:~/.ssh/` 후 AI가 배포 진행

## 7. 문서화 요청 (이번 작업)

### ✅ 효과적이었던 요구
> 지금까지 작업을 문서화해 줘.  
> 내가 어떻게 요구했고 네가 어떻게 작업했는지,  
> 다른 AI도 똑같이 만들 수 있을 정도로,  
> 앞으로 내가 어떻게 요구하면 같은 스타일로 만들 수 있는지,  
> `docs/` 폴더에.

→ **목적** (재구현 가능, 협업 가이드) + **형식** (docs/) + **포함 내용** 명시

## 8. AI에게 맡기면 좋은 것 vs 사람이 할 것

| AI | 사람 |
|----|------|
| 코드 작성·구조 설계 | 최종 UX "맛" 피드백 |
| 버그 재현·수정 루프 | SSH 키·비밀번호 복사 (보안) |
| 배포 스크립트 작성 | Windows→Linux 키 scp (1회) |
| 문서화 | 실제 서버에서 사용하며 불편한 점 전달 |
